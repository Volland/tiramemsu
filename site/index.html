Your agent’s brain loves Tiramemsu.

Memory that has layers, travels in time, and never forgets.

Tiramemsu is an embedded graph database on SQLite for agent memory. Every fact has its own id, so it can carry a confidence, a source or a belief, layer on layer. Every change is kept with when it was learned and when it was true. And an agent can recall by words and by meaning, today or as of any moment in the past, from one file.

What makes it different

Most agent memories are a vector index, a graph, or a log of notes. Tiramemsu is all three over one row shape, and it remembers when.

Facts about facts

Every statement has an id

Confidence, source, belief and correction are statements about statements, not a side table. Ask “why do I believe this?” in one query.

Two clocks

What we knew, and when it was true

Transaction time and valid time on every fact. Read memory as it was at any transaction, at any instant, or across its whole history.

Recall in the past

Search by meaning, as of then

Vector and text recall run inside the chosen view. An as-of view sees only the facts and vectors that existed then, so a past answer never drifts.

Never forget

History is guarded in the file

SQLite triggers refuse deletes and rewrites of facts, terms, transactions and vectors. Forgetting is a retraction that stays visible in history.

Evidence, not guesses

Every hit says why

Hits carry their confidence, confirmations, authors and age, ranked in a fixed, named order. Missing evidence is reported as missing, never invented.

Embedded

One file, no server

A Rust library over SQLite, with Python and Node bindings, an MCP server for agents, and the same engine in the browser.

One question, any moment

# What did the agent remember about the Lisbon offsite, as of last Tuesday?
# (embed() is your embedding model; MODEL its IRI, defined with define_embedding_model)
past = db.as_of(instant="2026-10-06T09:00:00Z")
for hit in past.recall("lisbon offsite", model=MODEL, vector=embed("lisbon offsite"), expand=2):
    print(hit.rank, hit.o, hit.evidence.confidence, hit.via)   # facts, their sources, why

Feature sets

A small Rust core over one SQLite file. Most of what follows is opt-in, so a store that does not ask for it behaves as before.

Remember

Layers

Provenance and belief stack

A statement is a row with its own id, so it can be the subject or object of other statements, to any depth. Retracting a fact retracts its layers.

Correct

Supersede, confirm, speculate

Correct a fact and its layers are replayed on the new one. Confirm a fact from a new source. Try changes in a with block that leaves no trace.

Schema

Cardinality, uniqueness, types

Predicates can be single-valued, unique or typed, checked on every write, with idempotent assert and parallel edges by create.

Review

Conflicts and import previews

See where values overlap in valid time, with every statement’s evidence, and dry-run a bundle from another memory before taking it.

Time travel

Bitemporal

Now, as of, history, valid at

Pick a view per query or per pattern, in Rust, SPARQL (SERVICE <tm:asOf/…>) and Cypher (USE AS OF).

Journeys

Paths that respect time

Who could have heard it from Ana after March 1st, with the earliest arrival, and whether the search was complete or cut at a cap.

Recheck

Answers that know they are stale

Saved queries are marked stale or recheck by later writes, once each; answers on a past view stay fresh.

Metagraphs

Structure with two clocks

Edges are nodes and can hold subgraphs. Nest, fold and unfold them, and ask how the structure looked last week. Read more.

Recall

New

Vector recall

Define a model, store the vectors your model computes, search exactly (cosine, dot, L2; f32 or f16). As-of views see only vectors stored by then.

New in 0.6

Vector indexes in queries

CREATE VECTOR INDEX, setEmbedding and DROP INDEX in Cypher; tm:vectorEmbedding in SPARQL Update. Cookbook.

New

Hybrid recall

Text and vector channels fused by reciprocal rank, expanded to each hit’s layers and subject facts, with via saying how each arrived.

Text

Find it by words

FTS5 recall over string values in any view, each hit with its evidence, from Rust, SPARQL and Cypher.

Evidence

Ranked, never invented

Ties break on confidence, confirmations, distinct authors and recency; absent evidence stays absent. Every policy has a name.

Query

Languages

SPARQL and Cypher

SPARQL 1.1 with RDF 1.2 annotations and openCypher share one IR and one semantics table. A relationship is also a :Statement node.

Paths

Native path engine

Reachability, trails and shortest paths as an automaton search that can cross layers and stay inside named graphs.

Graphs

Named graphs as tags

A graph is a node or a statement, and membership is one more layer. GRAPH, FROM and WITH need no new table.

Joins

Leapfrog triejoin

An opt-in native operator for cyclic patterns, with explain saying which route ran and why.

For agents and operations

Agents

An MCP server

tiramemsu-mcp gives Claude Code, Claude Desktop or any MCP client typed memory tools, from assert to recall, with a read-only mode.

Budgets

Deadlines and cancellation

Bound any call by time, rows, bytes or the wait for a reader. Over a limit is a typed error, never a silent prefix.

Bulk

Large loads in chunks

Import sessions commit in chunks, hold the write lease and refresh planner statistics once at the end.

Portable

Fact bundles

Export a fact with its layers and evidence, and import it into another memory idempotently.

Run anywhere

Embedded

One file, one crate

Rust over bundled SQLite (WAL, STRICT), behind a small executor trait. Python and Node bindings share one JSON bridge.

Browser

The engine in a Web Worker

SQLite compiled to WebAssembly, in memory or in OPFS, with the same file format, vector and text recall included.

Lean

Optional query front ends

Turn off default features and the crate links no parser or planner; transactions, views and recall still work.

Verified

Specs, tests and a paper

Fifty capability specs, property tests against brute force, closed W3C and TCK harnesses, and a formal model with proofs.

Quick start

The same story in three languages: a fact with a layer, a correction that keeps the layer, and the question “what did we believe before the correction?”. Pick a language.

pip install tiramemsu · Python 3.9 or later · PyPI

from tiramemsu import Database, Iri

V = "urn:tiramemsu:v:"  # written `v:` in queries
alice, works_at, acme, globex, confidence = (
    Iri(V + name) for name in ("alice", "worksAt", "acme", "globex", "confidence")
)
db = Database("memory.db")

# 1. A fact is a statement with its own id, so it can carry layers.
with db.transact() as tx:
    job = tx.assert_(alice, works_at, acme)
    tx.assert_(job, confidence, 0.8)
fact = tx.report.asserted[0]

# 2. Correct it: the layers are replayed on the new fact, nothing is deleted.
with db.transact() as tx:
    tx.supersede(fact, o=globex)

# 3. What is believed now, and what was believed before the correction?
q = "SELECT ?org WHERE { v:alice v:worksAt ?org }"
db.as_of(tx=1).sparql(q)   # acme
db.now().sparql(q)         # globex

# 4. The same store in Cypher: the confidence layer is a relationship property.
db.now().cypher("MATCH (p)-[r:worksAt]->(o) RETURN p, o, r.confidence AS conf")  # conf = 0.8

npm install @tiramemsu/node · Node 18 or later · npm

import { Database, iri } from "@tiramemsu/node";

const v = (name) => iri(`urn:tiramemsu:v:${name}`); // written `v:` in queries
const [alice, worksAt, acme, globex, confidence] =
  ["alice", "worksAt", "acme", "globex", "confidence"].map(v);
const db = Database.open("memory.db");

// 1. A fact is a statement with its own id, so it can carry layers.
const first = db.transact((tx) => {
  const job = tx.assert(alice, worksAt, acme);
  tx.assert(job, confidence, 0.8);
});

// 2. Correct it: the layers are replayed on the new fact, nothing is deleted.
db.transact((tx) => { tx.supersede(first.asserted[0], { o: globex }); });

// 3. What is believed now, and what was believed before the correction?
const q = "SELECT ?org WHERE { v:alice v:worksAt ?org }";
db.asOf({ tx: 1 }).sparql(q);   // acme
db.now().sparql(q);             // globex

// 4. The same store in Cypher: the confidence layer is a relationship property.
db.now().cypher("MATCH (p)-[r:worksAt]->(o) RETURN p, o, r.confidence AS conf"); // conf = 0.8

Recall by meaning

Your model computes the vectors; tiramemsu stores them with the facts and searches them exactly, in any view. embed() stands for your model.

db.cypher_write("CREATE VECTOR INDEX minilm IF NOT EXISTS OPTIONS {dimensions: 384}")
db.cypher_write("MATCH ()-[r:visited]->(:City {name: 'Lisbon'}) "
                "CALL tiramemsu.vector.setEmbedding(r, 'minilm', $v) YIELD stored RETURN stored",
                {"v": embed("visited Lisbon")})
db.now().cypher("CALL tiramemsu.vector.search('minilm', $q, {limit: 5}) "
                "YIELD subject, predicate, object, similarity RETURN *", {"q": embed("trip to Portugal")})
db.now().vector_search("urn:tiramemsu:v:minilm", embed("trip to Portugal"), limit=5)   # same hits

Where it stands

Tiramemsu is new: designed in September 2026 and grown in the open since. Here is what is measured, and what is not.

95 000 lines of Rust

Nine crates plus four bindings, 1 355 tests including property tests against brute force, 50 capability specs written before the code (OpenSpec) and a design graph kept in sync (lat.md).

SPARQL

634 of 781 in-scope W3C tests pass (66 more are skipped: named-graph data, unsupported formats). Every failing one is listed with a reason, and an unexpected result fails the build.

Cypher

2 615 of 3 880 openCypher TCK scenarios (67 %). Temporal types and a few dual-view cases are deferred and listed.

Speed

SPARQL point query 20 µs at 100 000 statements. Exact vector search over 10 000 768-d vectors in 12 ms, 100 000 in 134 ms; text plus vector recall in 10 ms at 10 000. Benchmarks and caveats.

Known limits. Vector search is exact, so its cost grows with the number of visible vectors; an approximate tier is the next step past about a million. The optional sign-bit prefilter is coarse: on real 100-d vectors it needs about 5 % of the corpus as candidates for 0.95 recall. The application computes embeddings, and a corrected fact needs a new one. As-of lookups slow down as one key collects many updates. Decimals come back as doubles in SPARQL. There is no network server; the MCP server is local and speaks stdio only. In the browser the database uses a rollback journal and refuses query budgets and bulk import.

The papers

Three preprints that write down the model behind tiramemsu and prove what it guarantees. CC BY 4.0, archived on Zenodo.

Paper 1 · consistency

Layered Bitemporal Graphs

One operator, the ground core, explains why retraction cascades, why the past stays grounded and how corrections keep their layers. Repairs it found shipped in 0.4.0.

Paper 2 · representation

Metagraph Encodings over Identified Triples

Metagraphs are cheap to write as identified triples. Reading them back needs exact image constraints, each one proved necessary.

Paper 3 · interoperability

When Is a Temporal Statement Store a Statement Graph?

Closed, acyclic sets export to OneGraph losslessly. The export kernel is the most you can keep, and the full history loses only correction cycles.
